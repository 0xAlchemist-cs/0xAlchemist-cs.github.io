一段长访谈里，值得留下来的话可能只有几句。但要把它们整理成一张可分享的图，仍然要经历不少步骤：听内容、找字幕、确认时间、选画面、排文字，再补上出处。

我将这些步骤整理成了 **Podcast Quote Pipeline**。它是一条由 Agent 工作说明与 Python 脚本配合完成的内容制作流程：从 YouTube 播客或访谈的原语言字幕中筛选候选句，保留对应时间戳，抽取视频画面，最后生成竖版金句拼图。

项目目前保留为私有仓库，这篇介绍它的功能和设计。

## 先把句子与来源对应起来

这类图片容易被误解的地方，是文字与画面的关系。一张看起来像视频截图的金句图，可能是后期排版的；一句读起来顺畅的话，也可能已经离开原来的语境。

因此，这条流程采用真实视频帧和该视频的自动字幕作为材料，再重新排版文字。**成品是字幕风格的编辑拼图，文字是后期叠加的，并非原片已经烧录好的字幕截图。**

```text
选择素材 → 取得视频与原语言字幕 → 清洗并重组句子
        → 筛选候选、人工核对 → 按时间戳抽帧
        → 合成竖版拼图 → 整理发布文案与排期
```

时间戳贯穿字幕与画面两个阶段。觉得某句话适合保留时，可以回到对应片段检查它指的是什么、是谁在说，以及前后有没有条件。

自动字幕也可能识别人名、术语或否定词错误。因此，候选句需要对照音频复核，重要表述尤其不能只看转录结果。

## 滚动字幕不能直接逐行摘抄

自动字幕常常随着说话不断刷新：先出现半句话，随后补上后半句，下一条又重复上一条的一部分。直接把每一行当成独立句子，就会得到大量重复和残缺内容。

提取阶段分成三个处理动作：

1. 去掉字幕中的内联时间标签和显示标记。
2. 对短时间内存在前缀重叠的滚动行进行合并，减少重复。
3. 将片段拼接到句末标点，保留首段时间，形成候选句。

随后再依据长度与主题关键词缩小候选范围，排除部分音乐、笑声等标记。

这是一套轻量规则，能减轻初筛工作，但仍然会受到字幕格式与标点质量影响。最终挑选还要看句子是否完整、离开上下文是否会误导，以及整张图是否围绕同一个主题。

主画面负责交代人物与场景，字幕带承载后续句子。统一版式后，每次制作主要需要决定：选哪几句、对应哪些画面，以及文字如何分行。

抽帧使用 ffmpeg，图片合成使用 Pillow。文字与画面分别处理，便于修改断行、字号或出处，而不必重新完成字幕提取。

当前模板还依赖 Windows 字体，并使用预先分好的文本行。更换系统或语言时，需要调整字体与排版；把多个长句直接塞进去，仍然可能出现拥挤或越界，需要检查成品。

## 将人工判断留在最影响质量的地方

这个项目包含两个不同层面的能力。

Agent 工作说明负责组织素材选择、字幕准备、抽帧、成图与排期；脚本负责字幕处理和图像合成。素材判断、最终选句、文字核对和发布审核仍然需要参与，当前脚本也没有接好社交平台自动发布接口。

这种划分让重复动作更容易复用，又能保留编辑选择。例如，一段字幕特别碎的闲聊，不一定值得强行拼出五句话；减少产出、换一个表达更完整的片段，往往更合适。

合成之前还应该检查几句内容放在一起之后的含义。来自不同时间的句子，即使分别准确，也可能因排列方式让读者误以为它们是一段连续发言。

## 跨语言复用，需要重新做编辑适配

目前的设计以葡萄牙语场景为起点。字幕清洗、时间戳抽帧和图片合成的整体结构可以复用，但迁移到其他语言时，仍有几项需要调整：

- 字幕轨道与识别质量：先确认拿到的是所需语言，并检查关键表述。
- 候选筛选规则：主题关键词、句末标点和长度范围需要匹配语言。
- 字体与断行：确认字符覆盖、可读性和每条字幕带的容量。
- 语境理解：由能够理解原语言的人核对含义，再决定是否分享。

尤其是中文等书写习惯不同的语言，不能只替换搜索词，就假定原来的筛选与排版参数仍然适用。

## 出处与授权要和内容一起进入流程

来源行能帮助读者回到节目，但署名本身不等于获得素材使用权。公开发布前，需要确认视频、人物画面和引用内容的使用条件，并遵守来源平台与发布平台的规则。

实际制作时，适合优先使用自己制作或已经获得授权的访谈素材。

成品还应清楚说明字幕经过重新排版，避免让读者误认成原视频的完整截图。涉及人物观点时，尽量保留节目、集数或其他可定位的来源信息，并在发布文案中提供回看入口。

## 把手工操作整理成可以继续修改的流程

这个项目的意义，在于把反复寻找、复制和排版的动作串起来：候选句能回到字幕，字幕能回到时间点，时间点能找到画面，成图也保留出处。

做完一张图之后，下一次可以沿用处理步骤，把注意力更多放在素材本身：这句话值得留下吗？表达准确吗？读者能否找到它原来所处的语境？

当这些问题仍然由人认真判断，自动化才真正节省了制作时间，而没有省掉内容应有的核对。
