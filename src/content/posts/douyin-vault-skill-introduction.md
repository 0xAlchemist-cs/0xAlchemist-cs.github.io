刷到一个有价值的视频，先收藏；过了几天，再想找其中某个观点，却已经记不清它在哪一条里。即使找回视频，也往往要重新拖动进度条。

我把这类内容整理流程做成了 [douyin-vault-skill](https://github.com/0xAlchemist-cs/douyin-vault-skill)。它把视频资料、语音转写、AI 内容分析和 Obsidian 建库串起来，让一次收藏最终变成可以检索、回看和自测的笔记。

我更看重其中的问题提炼环节：看完一段内容之后，留下几个具体的问题，下一次就有了重新思考它的入口。

## 从视频资料走到复习入口

项目由一份 Skill 工作说明和配套 Python 脚本组成。Skill 负责组织步骤与分析模板，脚本承担下载、转录和文件组装；浏览器收集资料与 AI 分析仍是流程中的独立环节。

```text
视频资料清单 → 下载与音频提取 → 语音转写
            → AI 整理摘要、观点和问题
            → Obsidian 视频笔记、主题页与总问题库
```

生成的知识库保留了几种不同用途的入口：

| 内容     | 用来做什么                             |
| -------- | -------------------------------------- |
| 视频笔记 | 查看来源、摘要、核心观点和待回答的问题 |
| 逐字稿   | 回到原始表达，核对摘要与答案           |
| 主题页   | 将同一主题下的内容集中起来             |
| 总问题库 | 按问题复习，有答案时展开查看           |
| 相关笔记 | 从当前内容继续阅读相近的笔记           |

每篇视频笔记还保留原片链接、日期和时长。提炼后的观点与来源保持联系，遇到转写错误或表述不清时，可以回到视频核对。

## 把“我看过”变成“我能回答”

AI 分析采用统一模板：一句话摘要、核心观点、提炼的问题，以及所属主题。问题需要具体到能够回答，而不只是留下宽泛的关键词。

例如，一段讲学习方法的视频，可以整理出这样的复习问题：

```markdown
## 提炼的问题

- 主动回忆与重新阅读分别要求学习者做什么？
- 怎样判断一个问题是否足够具体？
- 今天学到的概念，可以用在哪个实际场景？
```

这是格式示例。实际问题与答案应依据对应视频的内容整理。

建库脚本会读取分析文件中的问题；如果另外提供了匹配的 `answers` 文件，就生成 Obsidian 的折叠答案块，否则保留勾选问题。使用时可以先尝试回答，再展开答案，最后回看逐字稿。

这种组织方式让笔记有了后续动作：检索一个主题、回答一个问题，或者顺着来源检查某句话。

## 用稳定 ID 连接资料，用主题连接知识

补入新视频后，按时间排列的序号可能变化。因此，分析文件与逐字稿按视频 ID 匹配，展示序号只负责阅读顺序。这能减少重新排序时把分析内容配错视频的问题。

笔记之间的关联则由建库脚本计算：把标题、摘要、观点与问题拆成字符二元组，使用词频余弦相似度，并给相同主题的内容加分。每篇最多选出三篇达到阈值的相关笔记。

它使用的是轻量文本相似度，不需要额外部署向量数据库。链接适合用作阅读建议；同义表达、隐含联系和真正的论证关系，仍值得自己补充。

图谱配置还按主题页、视频笔记和问题清单设置颜色，并默认过滤逐字稿节点。这样，图谱更容易展示知识入口之间的联系，逐字稿则继续承担查证用途。

## 将耗时步骤拆开，方便恢复和更新

`transcribe.py` 先通过 ffmpeg 提取 16 kHz 单声道音频，再用 faster-whisper 转写，默认模型为 `large-v3`。它优先使用 CUDA，初始化失败时尝试 CPU int8，并输出文本、字幕文件和处理清单。

处理清单按视频 ID 记录状态，已经成功的转录可以跳过。资料收集、转录、分析和建库分别保存中间产物，出错时便于定位到具体阶段。

截至本文核对版本，仓库 README 记录了一次包含 111 条视频、553 个问题和 521 个带答案问题的整理案例。这些数字描述该次案例的规模；本篇依据公开说明与源码介绍流程。

运行流程需要准备 Python、ffmpeg 和转录模型等依赖。AI 分析由所使用的 Agent 或模型服务完成，是否产生费用取决于具体服务与运行方式。

## 在独立输出目录中生成知识库

这次源码核对有一个直接影响使用的重要细节：**当前 `build_vault.py` 会删除并重建指定的输出目录。** 因此，应把生成目录与日常手写笔记分开，更新前备份需要保留的内容。

在已经准备好 `videos.json`、`analysis` 和 `transcripts` 的数据目录后，建库入口是：

```bash
python scripts/build_vault.py ./data \
  -o ./generated-vault --themes ./themes.json
```

这里的 `generated-vault` 应当是专门用于生成的目录。README 提到的手动笔记保护，与当前这个版本的整目录重建行为存在差异，实际使用以脚本行为为准。

资料整理也应限定在自己有权访问和处理的内容范围内。仓库还记录了群聊整理的可选流程；涉及私人交流时，需要先明确参与者授权和保存范围。本文展示的是流程与笔记结构。

## 让收藏变成持续使用的材料

这个 Skill 的价值，在于把不同阶段的产物接起来：视频提供上下文，逐字稿保留表达，摘要帮助浏览，问题推动回忆，主题与链接支持继续探索。

对我而言，一个知识库有没有用，最终要看它能否帮助自己再次思考。能从一条收藏走到一个问题，再从问题回到原文，内容才逐渐进入自己的知识结构。
