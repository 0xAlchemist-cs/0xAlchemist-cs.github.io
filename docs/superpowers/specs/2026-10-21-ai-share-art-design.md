# 按全文设计分享图：Codex 创作模块

状态：2026-10-21 作者已确认详细设计，并要求先为《不必成为太阳》生成样图。基于 V1.2 PR #7 继续调整；具体图片与合并上线仍分别等待作者确认。

## 已确认的方向

作者选择“Codex 读全文并按需生图，确认后保存”。创作发生在协作写作时；网站和 GitHub Actions 继续静态、离线构建，不配置模型 API Key，不新增付费 API 依赖。内置生图工具使用当前会话可用能力和额度，不承诺无限免费生图。

本模块服务文章与项目的社交分享图，不修改原文、阅读界面、粒子背景或搜索验证方案。正文 `cover` 继续独立使用。旧文字卡片保留作为尚未配置 AI 图片的内容的回退。

## 创作与确认流程

1. 以 `blog/<slug>` 或 `projects/<slug>` 指定内容，读取当前完整 Markdown／MDX 和站点品牌信息。项目同时读取本地关联文章；每一个实际读取的来源都进入来源清单。默认不拉取远端仓库、网页或外部链接。
2. Codex 结合全文提炼核心观点、目标读者、语气、视觉隐喻、构图、配色、需要准确呈现的文字和避免事项，形成可审阅的设计简报。命令只负责整理完整输入与来源摘要，不把提取关键词伪称为 AI 阅读理解。
3. Codex 使用当前内置专门生图工具创作候选图。每篇内容可以有不同的画面构思，保留统一的作者与站点标识；不强制继续套用现有大白卡布局。
4. 默认让模型创作主体插画，标题与必要品牌文字由现有本地字体精确排版。生成候选时完成尺寸规范化和文字合成；画面内容的修改继续交给生图工具。候选的最终图为 1200×630 PNG，主体与必要文字都要保留安全边距。
5. 候选图在本地预览，不自动成为正式分享图。作者确认的是完成插画、标题及品牌排版的最终图；确认具体候选后才将该文件选为正式分享图，并记录确认状态、最终图片摘要、来源摘要和替代文字。保留主体原图及排版配置供后续修改。确认简报、生成候选图、确认合并是不同步骤。
6. 后续调整先生成新候选，保留已确认图片；在新候选确认前，现有分享图和线上版本继续可用。

第一张样图使用《不必成为太阳》。阅读重点是理想与现实之间的选择、有限性、自我价值及注意力的自主，而非仅因标题含有“太阳”就画一轮太阳。简报可用“普通人在自己的空间中认真创造，保有温和而独立的光”作为初始构思；这不是已确认的最终图稿。另两篇文章分别围绕“练习与延迟复习的闭环”和“分散图文消息到可追溯回放的过程”设计，不使用提分数字、虚构界面或收益曲线代替正文事实。

## 模块边界与资源

- 创作入口整理全文、来源清单及设计简报包；实际阅读理解和模型调用由 Codex 完成。GitHub Actions、Astro 页面和浏览器均不调用生图模型。
- 候选、预览和临时提示词保存在忽略的 `reports/share-art/`。已确认的图片、简报与清单保存在 `assets/share-art/<kind>/<slug>/`，随 PR 入库。这里是不会直接输出为网页资源的构建目录，仓库本身仍然公开。
- 每份清单记录格式版本、内容类型与 slug、实际来源路径及摘要、整体来源摘要、已确认最终图片的文件名与 SHA256、主体原图与排版配置、替代文字，以及创作工具和确认记录。不虚构工具未提供的底层模型名称。
- 来源路径只允许本仓库内容目录中的 Markdown／MDX。图片路径限制在对应资源目录，拒绝绝对路径、越界路径和符号链接。原始提示词、简报及字体不进入公开站点产物。
- 来源摘要基于实际读取的全文与 frontmatter，统一 CRLF 为 LF，按仓库相对路径排序后计算 SHA256。项目的关联文章变化也能触发复核提醒。

## 构建、回退与更新

已确认且有效的 AI 图片优先；没有清单时继续构建现有文字卡片。候选目录不作为批准依据。显式配置了正式图片却文件缺失、摘要不符、无法解码、尺寸错误或缺少确认／替代文字时，校验和构建失败，不能悄悄隐藏损坏配置。

构建直接输出已确认的最终 PNG，不再排版、裁切或叠加文字，确保发布的画面就是作者审阅的文件。需要改变图片上的标题、品牌、字体或排版参数时，生成新候选并重新确认，不能由 CI 在确认后静默修改。

正文变化导致来源摘要过期时，审计明确提醒复核，保留已确认图片，不自动重生或删除。若复核后认为图片仍适合，只更新复核记录与来源摘要；若需要换图，走新候选与确认流程。生成后、确认前正文再次变化时，导入提示来源已变化，必须重新核对当前正文再确认。

最终图片继续位于 `/og/blog/<slug>-<hash>.png` 或 `/og/projects/<slug>-<hash>.png`。地址哈希覆盖实际采用的最终图片内容、对应已确认的排版参数及卡片／品牌／字体版本，使替换已确认图稿或文字样式后得到新地址。OG、Twitter Card 与文章 JSON-LD 继续共用同一结果。

草稿与示例沿用现有生产可见性规则；其图片不进入生产产物、Sitemap、搜索索引或 RSS。首页等普通页面继续使用默认站点分享图。

## 验证与交付

- 校验全文输入没有被静默截断、文章与项目同 slug 不冲突、CRLF/LF 摘要一致、项目关联文章可检测变更。
- 覆盖未配置回退、已确认图片优先、候选不发布、来源过期提醒、图片损坏／摘要错误／越界路径拒绝，以及改图后地址变化。
- 扩展现有分享审计与离线预览，显示图片来源、确认状态和待复核状态；继续验证 1200×630 PNG 解码、统一元数据、隐藏内容隔离及无构建网络依赖。
- 生图不纳入自动化测试，不伪造真实模型测试通过。代码通过既有 `verify`、必要的桌面／手机浏览器回归及 Ubuntu CI；作者实际检查候选图的主题表达、文字、构图与小图可读性。
- 提供写作与换图指南，并在当前 PR 更新预览和检查证据。作者确认具体图片后才选用，确认合并后才部署；部署后继续做线上图片与页面元数据检查。Google／Bing 平台操作仍留待后续。

## 方案取舍

所选方案把创作与发布解耦，便于反复调整画面，并保持发布流程不依赖模型服务。每次 Actions 自动调用 API 的方案需要密钥、计费和重试配置，本轮不采用；完全手工上传任意图片虽改动较少，却无法保留全文设计依据与过期提示，也不作为本模块的完成标准。
